- Work in a sibling worktree `SEC-RAG-deploy` on branch `deploy`. Lay down eval rows with merges, never rebases.

## Review Focus

1. **Spoofed client IP.** A visitor who sends their own `Fly-Client-IP` header must not get a fresh per-IP quota. Fly's edge overwrites that header; Task 8 Step 3 proves it against the live app.
2. **Rejected requests don't spend quota.** A blank or overlong question (422) must not use up quota. A 429 must not record a hit either, otherwise a client retrying in a loop would lock itself out for good. Task 1 pins both.
3. **A browser that hits the limit sees why.** The 429 must carry CORS headers, or the browser hides the body and the user sees "Failed to fetch". The UI must show the server's sentence, not "status 429". Task 1 (CORS assertion) and Task 3 pin this.
4. **A conversation resumed after the retention window.** Pruning must remove a whole idle conversation, never only its oldest turns. Otherwise `turn_index = count(*)` would reuse a low index and the history order would scramble. Task 2 pins this.
5. **First query after restore or cold boot.** Before stats exist, the planner may pick a seq scan or the HNSW post-filter path (see CLAUDE.md, retrieval-measurement gotcha), and the model must load without network. Task 4 runs the image with `--network none`, and Task 5 runs `VACUUM ANALYZE` before any query.

```python
"""Per-IP and site-wide caps on POST /ask.

Every answer is 3-5 paid Haiku calls and the demo has no accounts, so these
caps are what bounds the bill (the Anthropic console spend limit is the
backstop, not the plan). State is in-process: correct only because the deploy
runs one machine with one uvicorn worker (backend/fly.toml). A second process
would keep its own counters and double the effective limits.
"""

from __future__ import annotations

import threading
import time
from collections import deque
from collections.abc import Callable, Mapping

HOUR = 3600.0
DAY = 86400.0


class RateLimited(Exception):
    def __init__(self, message: str, retry_after: int):
        super().__init__(message)
        self.message = message
        self.retry_after = retry_after


class AskLimiter:
    def __init__(
        self,
        per_ip_per_hour: int,
        daily_cap: int,
        clock: Callable[[], float] = time.time,
    ):
        self.per_ip_per_hour = per_ip_per_hour
        self.daily_cap = daily_cap
        self._clock = clock
        # /ask is a sync endpoint, so FastAPI runs it on a threadpool.
        self._lock = threading.Lock()
        self._hits: dict[str, deque[float]] = {}
        self._day = -1
        self._day_count = 0

    def check(self, ip: str) -> None:
        """Record one /ask for `ip`, or raise RateLimited without recording it."""
        with self._lock:
            now = self._clock()
            # Epoch seconds are UTC, so this is the UTC day number.
            day = int(now // DAY)
            if day != self._day:
                self._day, self._day_count = day, 0
                # Drop visitors idle for an hour; bounds the dict by a day's traffic.
                self._hits = {k: v for k, v in self._hits.items() if v and v[-1] > now - HOUR}
            if self._day_count >= self.daily_cap:
                raise RateLimited(
                    "The demo has reached its question limit for today."
                    " It resets at 00:00 UTC.",
                    retry_after=int((day + 1) * DAY - now) + 1,
                )
            hits = self._hits.setdefault(ip, deque())
            while hits and hits[0] <= now - HOUR:
                hits.popleft()
            if len(hits) >= self.per_ip_per_hour:
                raise RateLimited(
                    f"You've asked {self.per_ip_per_hour} questions in the last hour,"
                    " the limit for this demo. Try again in a little while.",
                    retry_after=int(hits[0] + HOUR - now) + 1,
                )
            hits.append(now)
            self._day_count += 1


def client_ip(headers: Mapping[str, str], peer: str | None, header: str | None) -> str:
    """The visitor's address. `header` is trusted only when configured: on Fly
    the edge proxy overwrites Fly-Client-IP, so a client cannot forge it there.
    Anywhere else the header is attacker-controlled, so it is ignored."""
    if header:
        value = headers.get(header) or headers.get(header.lower())
        if value:
            return value.strip()
    return peer or "unknown"
```

### Task 2: Conversation retention

### Task 5: Production database (Supabase)

All commands run in **Git Bash** from the repo root. `export MSYS_NO_PATHCONV=1` comes first in every shell: without it, Git Bash rewrites the container path `/tmp/edgar.dump` into a Windows path and `pg_dump` fails with `could not open output file`. This was hit for real on 2026-10-30.

- [x] **Step 1: Measure the corpus as it will land** (done 2026-10-30)

The scratch restore came to **247 MB** after `VACUUM ANALYZE` (local DB: 398 MB, the difference is bloat). Breakdown: chunks 96 MB, sentences 58 MB, table_cells 53 MB, filings 29 MB. That fits Supabase Free's 500 MB. `/tmp/edgar.dump` (78 MB) is still inside the `db` container. Re-run this only if the corpus changes before deploy or the container is recreated:

```bash
export MSYS_NO_PATHCONV=1
docker compose exec -T db pg_dump -U user -d edgar_answers -Fc --no-owner --no-privileges \
  --exclude-table-data=conversation_turns -f /tmp/edgar.dump
docker compose exec -T db createdb -U user size_probe
docker compose exec -T db pg_restore -U user -d size_probe --no-owner --no-privileges /tmp/edgar.dump
docker compose exec -T db psql -U user -d size_probe -c "VACUUM ANALYZE"
docker compose exec -T db psql -U user -d size_probe -Atc "SELECT pg_size_pretty(pg_database_size('size_probe'))"
docker compose exec -T db dropdb -U user size_probe
```

- [ ] **Step 2: Create the Supabase project** (Dylan, in the dashboard)

Create a new project in region **East US (North Virginia) / us-east-1**. Free orgs get two active projects, and this is the second. Save the database password somewhere safe. Then go to **Connect → Session pooler** and copy that URI (host `aws-0-us-east-1.pooler.supabase.com`, port **5432**). Don't use the "Direct connection" string: on Free it is IPv6-only, and your home network and Docker may not have IPv6. Don't use the "Transaction pooler" (port 6543) either: it breaks psycopg 3's prepared statements (deployment.md §2.3-11). Session mode supports them. Put it in `backend/.env.production` as `PROD_DATABASE_URL=postgresql://postgres.<ref>:<password>@aws-0-us-east-1.pooler.supabase.com:5432/postgres?sslmode=require`. That file is gitignored by `.env.*`. Don't paste it in chat.

- [ ] **Step 3: Restore into Supabase**

```bash
export MSYS_NO_PATHCONV=1
set -a; . backend/.env.production; set +a
docker compose exec -T -e PROD_DATABASE_URL db sh -c \
  'pg_restore --no-owner --no-privileges --no-comments -d "$PROD_DATABASE_URL" /tmp/edgar.dump'
docker compose exec -T -e PROD_DATABASE_URL db sh -c 'psql "$PROD_DATABASE_URL" -c "VACUUM ANALYZE"'
```

Expected: the restore finishes. Supabase's database already has a `public` schema, so pg_restore may print `schema "public" already exists` and end with `errors ignored on restore: N`. That one error is harmless. **Any other error is not**: read every line, and treat errors on `CREATE EXTENSION vector`, `CREATE TABLE`, `COPY` or `CREATE INDEX` as a failure to fix before going on. The HNSW index rebuilds during the restore. `VACUUM ANALYZE` is not optional: without stats, the planner's choice between HNSW and a seq scan is arbitrary (CLAUDE.md, retrieval-measurement gotcha).
